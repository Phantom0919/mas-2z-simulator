# 中二野人实验室 · v3.5

一个**零依赖的 Node.js 高中生活模拟器**（原名「马鞍山二中模拟器」，v3.0 起改名——
搜不到校名，但"中二"两个字摆在那儿，玩的人一眼知道写的是哪所学校；
游戏内的校名一律只写「二中」，与任何真实学校无关）。你是二中的高一新生，三年、六个学期、36 个星期，
每个星期要在一堆选择里活下来：主行动 + 周末安排，一共 **72 次决策**；高考之后还有最后一关——**填志愿**。

同时提供 **终端版（CLI）**、**网页版（Web UI）**、**桌面客户端**和**安卓 APK**，共用同一份纯逻辑引擎。
`docs/` 目录是一个可以直接扔到 GitHub Pages 的**官方发布页**：在线试玩 + 一键下载 + 交流频道入口。

> 🎮 玩法与数值变化见 [CHANGELOG.md](./CHANGELOG.md)。
> 🗺️ 下一步做什么、以及这个项目是怎么分工的，见 [ROADMAP.md](./ROADMAP.md)。
> ⚠️ 本模拟器中的事件、人物、分数线和结局**全部为虚构娱乐内容**，与任何真实学校、机构、个人无关；
> 游戏里的校名一律只写「二中」，不对应任何一所真实中学。

## 快速开始

要求 **Node.js >= 18**（用到 `node:test`、`fetch`、`Intl.Segmenter`）。**不需要 npm install**。

```bash
cd mas-2z-simulator

npm start            # 终端版：进入开局向导（选科 / 天赋 / 背景 / 目标）
npm run web          # 网页版：http://127.0.0.1:3210
npm test             # 跑测试（引擎 + 服务端 + 前端 + 发布页，407 条）
npm run sim          # 数值平衡报告（9 种策略批量跑）
npm run gallery      # 查看结局图鉴与历史战绩
npm run pages        # 生成 / 更新官方发布页（docs/）
npm run pages:serve  # 本地预览发布页：http://127.0.0.1:8080
```

### 终端版常用命令

```bash
node src/cli.js                                   # 开局向导，交互游玩
node src/cli.js --track history --electives politics,geography
node src/cli.js --traits memory,nightowl --background magang --goal top2
node src/cli.js --endless                         # 自由模式
node src/cli.js --auto --strategy olympiad        # 自动打完一整局
node src/cli.js --auto 12 --json --quiet          # 只输出 JSON 摘要
node src/cli.js --load saves/小明-1234.json       # 读档继续
node src/cli.js --gallery                         # 结局图鉴
node src/cli.js --list-strategies                 # 9 种自动策略
node src/cli.js --auto --relations                # 自动打完后打印人物关系树
node src/cli.js --auto --story                    # 自动打完后打印七条剧情线

# 自定义人物（v2.5）
node src/cli.js --nickname 闪电 --personality sharp --flaw frail \
                --points "intelligence:5,mood:1,math:2" --legacy 3
node src/cli.js --difficulty custom --custom "gain:1.5,forgetScale:0.5,points:18,lopsided:1"

# 志愿填报、热更新与推送（v2.6 / v2.7）
node src/cli.js --auto --volunteers "3 7 2 1 5 9"   # 指定志愿（编号见对局里打印的志愿表）
node src/cli.js --auto --no-volunteers             # 跳过志愿填报，直接按分数录取（做对照用）
node src/cli.js --content                          # 打印当前内容包状态
node src/cli.js --pack web/content/official-pack.json   # 启动时加载一个内容包（热更新）

# AI 对战（v3.0）
node src/cli.js --mode versus --rival hard         # 和一个卷王型 AI 同榜打三年
node src/cli.js --auto --mode versus --rival real --json --quiet   # 自动对战 + JSON 摘要（含 versus 字段）
```

交互命令：`数字` 行动，`s` 状态，`l` 日志，`e` 成绩单，`b` 商店，`g` 图鉴，
`r` **人物关系图**，`t` **故事线**，`w` 存档，`q` 退出，回车 = 重复上次。
完整参数见 `node src/cli.js --help`（属性点能用的键也列在里面）。

> 🎲 同一组 **种子 + 名字 + 难度 + 选科** 会得到一模一样的三年（**包括这一届所有人的姓名**）；
> `traits` / `background` / `goal` / `personality` / `flaw` / `points` / 自定义关系人物的名字
> 都不参与随机序列，所以想做"对照实验"可以直接换构筑再跑同一个种子。
> 加 `--wizard` 还能在管道里脚本化地走一遍开局向导。

### 官方发布页（GitHub Pages，v2.8）

`docs/` 就是一个**可以直接发布的静态站点**：首屏讲清这个游戏是什么、七张真实截图、
三种打开方式、版本时间线、常见问题、腾讯频道入口和「关于我们」。
它没有任何外链（没有 CDN / 字体 / 统计脚本），所以墙内能开、断网也能开。

```bash
python tools/build-pages-shots.py   # ① 界面改过之后：把 shots/ 的验收截图压成 JPEG + 生成分享图
node tools/build-pages.mjs          # ② 每次发版：同步在线试玩副本 + APK + 推送源 + 可上传的 zip
node tools/serve-pages.mjs          # ③ 上传前先在本地看一遍（默认 8080，手机也能连）
```

- **在线试玩**：`docs/play/` 是 `web/` 的副本，`docs/src/` 是按 import 图自动收集的引擎模块
  （和 APK 用的是同一套 `tools/module-graph.mjs`）。所以**分享一个链接就能开局**，
  不用先下载 0.5 MB 再"允许未知来源"。副本由测试盯着和 `web/` 逐字节一致。
- **页面上的数字不手写**：APK 的版本 / 体积 / SHA-256 由 `tools/build-pages.mjs` 从真实产物算出来，
  写进 `docs/download/latest.json`，页面加载后填进去。
- **上传**：把 `docs/` 推到仓库（`main` 分支）→ Settings → Pages → Source 选
  "Deploy from a branch"、目录选 `/docs`；或者直接用生成的
  `dist/中二野人实验室-<版本>-发布页.zip`（解压后就是站点根目录）。
  手写文件（`index.html` / `assets/style.css` / `assets/site.js`）不会被构建脚本覆盖。
- **顺带的收益**：GitHub Pages 自带 CORS 头，所以 `docs/content/` 里的
  `update-manifest.json` + 内容包可以**直接当 v2.7 的推送源**（手机上的离线版也能直拉）。

### 🏆 玩家排行榜（v3.1）

GitHub Pages 是纯静态的，没有数据库——所以排行榜接的是 **Supabase 免费版**（Postgres + REST）。
前端只放 **anon key**（Supabase 设计上公开的"publishable"密钥），门禁全在数据库的 RLS 策略里：
匿名**只能读、只能插入，不能改也不能删**别人的记录。

**没接后端时**：只有**本机榜**（存在 localStorage，刷新/关机再开都还在），页面**一个请求都不发**——
和热更新一样是"离线优先"。断网、墙上、后端挂了，都只是降级成本机榜，绝不挡游戏。

接后端（大约 5 分钟）：

1. https://supabase.com 注册 → New project（免费版够用，区域挑离你近的）
2. 左侧 **SQL Editor → New query** → 把 [`tools/leaderboard-schema.sql`](./tools/leaderboard-schema.sql) 整个粘进去 → Run
3. 左侧 **Project Settings → API**：抄下 **Project URL** 和 **anon public key**
4. 填进 [`web/content/leaderboard.json`](./web/content/leaderboard.json)：

   ```json
   {
     "format": 1,
     "supabase": {
       "url": "https://xxxxxxxxxxxx.supabase.co",
       "anonKey": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9....",
       "table": "leaderboard"
     }
   }
   ```

5. `npm run pages && npm run apk` → 发布页和 APK 都读同一份配置（游戏里走的也是这个地址）。

**接完一定要跑一次自检**：

```bash
node tools/check-leaderboard.mjs
```

它会读一次榜单、写一条「自检员」记录、再试着**改分数**和**删记录**（这两步必须失败，说明 RLS 生效了），
最后打印清理用的 SQL：`delete from public.leaderboard where nickname = '自检员';`

> ⚠️ **国内网络的一个现实问题**：`*.supabase.co` 挂在 Cloudflare 上，部分网络会**按 SNI 阻断**
> （TCP 能连上、TLS 握手被重置）——本项目的开发机就是这种情况，`node tools/check-leaderboard.mjs`
> 会直接报 `unreachable`。**游戏本身不受影响**：读不到就退回本机榜，玩家照常玩，只是看不到全服榜。
> 如果全服榜对你很重要，可选：给 Supabase 配自定义域名（付费功能，需要自己有域名）、
> 或者换成国内后端（腾讯云开发 / 自建 + 备案域名）。

> 🛠️ **想让国内也能稳定看到榜单**：最省事的做法是**套一层自己的域名**，仓库里两种后端都备好了：
>
> | 路线 | 代码 | 说明 |
> | --- | --- | --- |
> | **A. Cloudflare Worker + D1**（推荐） | [`tools/cloudflare/worker-d1-leaderboard.js`](./tools/cloudflare/worker-d1-leaderboard.js) + [`d1-schema.sql`](./tools/cloudflare/d1-schema.sql) | 数据在自己的 Cloudflare 账号里（免费：每天 10 万请求 / 5GB），不要 Supabase；"只能读和插、字段校验、同一昵称 60 秒一条"全在 Worker 里 |
> | B. Worker 反代 Supabase | [`tools/cloudflare/worker-supabase-proxy.js`](./tools/cloudflare/worker-supabase-proxy.js) | 保留现有数据和 RLS，Worker 只做白名单转发 |
>
> 两种对外形状一样（`/rest/v1/<表>`、`apikey` 头、snake_case 列名），所以**前端只改配置文件**：
> 新形状 `backend: { type, url, apiKey, table }`，旧的 `supabase: { url, anonKey, table }` 继续认。
> 部署步骤见 [`tools/cloudflare/README.md`](./tools/cloudflare/README.md)（约 10 分钟）；
> 边界由 `test/cloudflare.test.js` 的 **21 条**测试盯着（假上游 + 假 D1，不联网、不需要 wrangler）。
> 前提同样是：**得有一个域名**；`*.workers.dev` 在国内一样经常打不开，等于没解决。

| 榜 | 排序规则 | 给谁看 |
| --- | --- | --- |
| 🎯 **总分榜** | 高考总分 → 年级名次 → 成就数 | 追分数的人；每行带难度徽章（难度不同分数不可比） |
| 📖 **收集榜** | 结局图鉴解锁数 → 成就收录数 → 总分 | 多周目玩家；两条线都排 |

几条刻意的设计：

- **同一个昵称只留最好的一条**——不然一个人打十局就把榜刷满了；
- **并列同名次**，下一位按真实条数继续（1、1、3）；
- **可复核**：条目里带随机种子和构筑摘要，同种子同构筑必然跑出同一局。这是这个项目能给的最高等级公信力；
- **诚实**：客户端提交的成绩**防不了作弊**，我没有假装能防。数据库那层只做范围校验（分数 0~750、昵称 1~16 字、模式枚举）——
  它的作用是挡住手滑和脏数据，不是挡住有心人；
- 榜单脏了你自己清（控制台执行）：`delete from public.leaderboard where id in (...);`
- 排序 / 并列 / 去重全在 [`src/leaderboard.js`](./src/leaderboard.js) 里，**官网和游戏共用同一份**，不会两处各写一遍。

### 热更新：怎么把新内容装上

三种入口装的是同一个东西（一个内容包 JSON）。**同时只有一个包生效，随时能一键回官方内容**：

| 入口 | 怎么操作 | 适合 |
| --- | --- | --- |
| 📱 手机 / 网页 | 顶栏「🔄 内容包」→ 选 JSON 文件 / 粘贴 JSON / 填 https 地址 → 应用（安卓 APK 和网页版是同一套界面） | 玩家 |
| 💻 CLI | `node src/cli.js --pack 包.json`（`--pack` 不给值则读 `saves/content-pack.json`）；`--content` 看当前状态 | 调试 / 做对照实验 |
| 🌐 服务端 / 桌面版 | `POST /api/content/apply`，body 传 `{ text }` / `{ url }` / `{ pack }`；`GET /api/content` 查状态、`POST /api/content/reset` 回官方。服务端会落盘到 `saves/content-pack.json`，重启自动重放 | 联网分发 / 自动化 |

- 装完界面会报**包名 / 版本 / 校验和 / 改动条数**，并**立刻生效**——不用重开一局，下一个事件就可能撞上新内容。
- 网页版把包存在 localStorage，刷新页面自动重放；服务端 / 桌面版落盘在 `saves/content-pack.json`。
- 手写 JSON 的常见坑会自动兜住并点名：**UTF-8 BOM**（记事本"另存为 UTF-8"就会带上）、零宽字符、中文标点 `“”，：`、尾随逗号、`//` 注释。
- 校验不通过就**整包拒装**，不会把游戏留在"改了一半"的状态。

### 热更新：内容包怎么写

游戏内容（事件 / 道具 / 天赋 / 平衡）现在是**可替换的数据**，玩家不改装 APK 也能拿到更新。
一个内容包就是一个 JSON：

```json
{
  "format": 1,
  "meta": { "name": "秋季内容包", "version": "2.6.1", "author": "官方" },
  "requires": { "app": ">=2.6.0" },
  "events": [
    { "id": "pack_rain_library", "name": "雨夜图书馆", "icon": "🌧️", "kind": "choice", "weight": 9,
      "text": "……", "choices": [ { "id": "carry", "label": "……", "hint": "……", "outcome": "……",
      "effect": { "stats": { "mood": 3 } } } ] }
  ],
  "items": [{ "id": "thermos", "name": "保温杯（枸杞版）", "price": 260 }],
  "balance": { "eff": { "gainScale": 0.82 }, "difficulty": { "normal": { "forgetScale": 0.95 } } }
}
```

- 合并规则：**同 id 覆盖、新 id 追加**；同一时间只生效一个包（新包基于内置内容合并，不会层层套娃）。
- 从真实源码生成快照：`node tools/build-content-pack.mjs --out web/content/baseline-snapshot.json`
  （两次运行字节一致、无 BOM、SHA-256 自证）；对比两个包：`--diff <旧包>`。
- 现成可玩的示例：`web/content/official-pack.json`（2 个新事件 + 保温杯 + 两处平衡调整）。
- 校验不过就**整包拒装**，错误会定位到"事件 id + 第几个选项 + 字段"。
- 一个诚实的限制：`cond` / `effect` / `outcome` 是函数，JSON 装不下，快照会**跳过并逐条点名**这些事件。

### 给玩家推送更新（更新清单）

上面那套热更新解决的是**拉**——玩家得自己找到包再导入。要**推**，就配一个更新清单（manifest）：

```bash
# ① 生成内容包，顺手记下摘要里的「校验和」（8 位十六进制，就是清单要填的 checksum）
node tools/build-content-pack.mjs --out web/content/weekly-pack.json \
     --name "周更内容包" --version 2.7.1
#    web/content/update-manifest.json 是一份可以直接抄的清单

# ② 把包和清单放到任意 https 上（对象存储 / GitHub Pages / 自己的服务器），然后让游戏知道清单在哪：
node src/server.js --update-url https://example.com/mas2z/update-manifest.json
#    也可以：环境变量 MAS2Z_UPDATE_URL，或写进 web/content/update-endpoint.json 的 manifest 字段
#    （网页版和手机 APK 都读 update-endpoint.json；**默认留空 = 不检查更新**，离线优先）

# ③ 自己先看一眼结论，别让玩家当小白鼠
node src/cli.js --check-update https://example.com/mas2z/update-manifest.json
node src/cli.js --check-update web/content/update-manifest.json      # 本地清单文件也行
```

清单长这样（`url` 可以写相对路径，相对清单自己的地址解析——这样"游戏服务端自己托管内容"不用写死域名）：

```json
{
  "format": 1,
  "channel": "stable",
  "latest": {
    "version": "2.6.1",
    "url": "official-pack.json",
    "checksum": "d65d6c65",
    "notes": "秋季内容包：雨夜图书馆、冬季长跑接力、保温杯（枸杞版）",
    "releasedAt": "2026-10-01",
    "requires": { "app": ">=2.6.0" },
    "auto": false,
    "mandatory": false
  }
}
```

- 客户端启动时 `GET /api/update`，**服务端代拉清单**并给出结论（顺带绕开 CORS：对象存储不一定配了跨域头）
- 有新内容时顶部弹一条横幅：**立即更新 / 稍后 / 忽略这个版本**。忽略只忽略这一版，下次有新版本还会提示
- 清单写 `"auto": true` → 静默安装；写 `"mandatory": true` → 不提供"稍后 / 忽略"
- **判断"变了没有"只看 checksum，不看版本号**——所以"版本号没动、内容改过"照样能推下去
- **绝不自动降级**：清单版本比本地低时只提示、不覆盖（玩家手里的包可能比线上新）
- 地址准入：只允许 https，或回环 / 内网的 http；`file:` / `data:` / `169.254.169.254`（云元数据端点）一律拒绝
- 拉不到、清单坏了 = **什么都不做**：横幅不弹、报错不弹，游戏该玩玩（`unreachable` 和 `invalid` 在界面上也是两句话）

`web/app.js` 只多做了一件事：**检测到 `window.mas2z` 时优先使用原生对话框与菜单命令**，在浏览器里则退回原来的行为。

### 安卓客户端（APK）

```bash
npm run apk:sdk        # 第一次：下载 Android SDK 到项目里的 .android-sdk/（约 300MB，不需要 Android Studio / Gradle）
npm run apk            # 出包：dist/中二野人实验室-2.4.0-debug.apk（约 0.27 MB）
```

装到手机上（三选一）：

```bash
adb install -r "dist/中二野人实验室-2.4.0-debug.apk"   # 有 adb
# 或者把 apk 传到手机点开安装（需要允许"安装未知来源应用"）
# 或者直接用浏览器打开网页版 → 菜单里选"添加到主屏幕"（PWA，见下）
```

APK 是**完全离线**的：游戏逻辑（`src/engine.js`）和界面都在包里，不需要任何服务端。

| 要点 | 做法 |
| --- | --- |
| 📦 **零 Gradle** | `tools/build-apk.mjs` 直接调 build-tools：`aapt2 compile/link → javac → d8 → jar → zipalign → apksigner` |
| 🧩 **离线引擎** | `web/local-api.js`：在页面内实现与 HTTP 接口完全一致的 `/api/*`，前端自动探测，没有服务就用它 |
| 🌐 **虚拟域名** | 页面通过 `https://mas2z.local/` 加载，`MainActivity.shouldInterceptRequest` 从 assets 直接返回文件——因为 `file://` 下 ES 模块会被 CORS 拦掉 |
| 💾 **进度保存** | 开启 `DomStorage`，自动存档和跨局图鉴都存在 WebView 的 localStorage 里 |
| 🔐 **签名** | 自动生成 `android/debug.keystore` 调试签名（v1+v2+v3），可直接侧载 |
| 📱 **适配所有机型** | minSdk 21（Android 5.0+）、targetSdk 34、**不锁横竖屏**（`fullUser`）、声明支持小屏到平板与任意密度、`resizeableActivity` 支持分屏/折叠屏；刘海屏用 `windowLayoutInDisplayCutoutMode=shortEdges` + 网页的 `viewport-fit=cover` + `env(safe-area-inset-*)`；旋转/分屏/改系统字体都不重建 Activity；无网络权限 |
| 🖐 **触摸友好** | `@media (pointer: coarse)` 下按钮至少 40px 高、行动卡片 64px，`touch-action: manipulation` 去掉 300ms 延迟 |

> 顺带记录两个踩过的坑（脚本里都绕开了）：Windows 上 Node 不能直接 spawn `.bat`（所以 d8 / apksigner 用 `java` 跑主类）；
> 这台机器的 `aapt2` 打不开绝对路径，而且用 `-A` 加资产时会把分隔符写成反斜杠（`assets\www\index.html`），
> Android 的 AssetManager 只认正斜杠——所以资产改由 `jar` 添加，并且全部改用相对路径。

如果你只想在手机上跑、不想装 SDK：直接打开网页版（`npm run web` 后用同一局域网的手机访问），
或者在支持的环境里用 PWA 安装——`web/manifest.webmanifest` 已经配好，浏览器菜单里选"添加到主屏幕"即可离线使用。

> ℹ️ `minSdk 21` 只是"能装"的门槛，实际还需要**比较新的 Android System WebView**

## 玩法

### 1. 自定义人物（开局构筑）

开局页是一台"捏人"机器，7 个区块从上到下：

- **这个人是谁**：姓名（可 🎲 随机）、性别、**外号**（自己填或随机，会进开学日志和顶栏）、
  **头像**（14 个 emoji，出现在日志、开局构筑栏和关系图里）。
- **性格（选 1）**：平常心 / 阳光 / 沉稳 / 锋芒 / 慵懒 / 敏感 / 硬气。
  性格和天赋是两套东西——天赋给能力，性格给脾气，所以性格允许带负面（`锋芒` 学习 +12% 但心情消耗 +30%）。
- **天赋（选 2）**：影响学习收益、心情消耗、疲劳增长、初始智力、竞赛成功率、考试波动、遗忘速度……
- **缺陷（选 0~1）**：近视六百度 / 零花钱很少 / 睡眠浅 / 从小体弱 / 开窍晚，用短板换 **4~6 点属性点**。
- **属性点**：难度给预算（轻松 16 / 正常 12 / 困难 9 / 真实 7 / 自定义自己调），自己投——

  | 投向 | 1 点换 | 上限 | | 投向 | 1 点换 | 上限 |
  | --- | --- | --- | --- | --- | --- | --- |
  | 智力 | +1 | 12 点 | | 综合素质 | +3 | 10 点 |
  | 体质 | +2 | 12 点 | | 单科底子 | +4 分 | 每科 3 点 |
  | 心情 | +3 | 8 点 | | 零花钱 | +200 元 | 3 点 |
  | 社交 | +3 | 10 点 | | | | |

- **选科**：首选 `物理` 或 `历史`，再从 `化学 / 生物 / 政治 / 地理` 里选 2 门。高考满分 750 = 语数英各 150 + 三门选考各 100。
- **家庭背景（选 1）**：初始零花钱、父母关系、初始知识。
- **高考目标（选 1）**：清北 / 985 / 一本 / 保送 / 特长路线 / 快乐毕业 / 恋爱圆满 / 攒钱 / 完整读完三年。
  结局时会判定**达成 / 未达成**，并记进档案。
- **自定义关系人物**：同桌、死党、老对手、心动对象的**名字和性别都能自己定**，
  正文里的称呼（"小美"）和代词（他 / 她）会跟着变；不填就随机。
- **难度与节奏**：五档难度 + 每学期周数 + 随机种子 + 自由模式。
  选「自定义」会多出 8 根滑杆（成长 / 遗忘 / 开局底子上下限 / 零花钱 / 事件频率 / 考试波动 / 属性点 / 偏科）。

三件"少填一会儿"的工具：

| 工具 | 说明 |
| --- | --- |
| 🎲 **随机捏一个** | 名字、外号、头像、性格、天赋、缺陷、属性点全部随机 |
| 🗂️ **9 套角色模板** | 卷王 / 体育生 / 文艺青年 / 社牛 / 竞赛生 / 躺平 / 偏科怪才 / 均衡派 / 梭哈怪，一键填好（选科留给你自己点） |
| 💾 **角色卡** | 把当前配置存进浏览器（最多 30 张），下次一键读取；换设备用导出存档 |

> 🔁 **多周目传承**：每玩满 2 局，新一局多得 1 点属性点（最多 6 点）。图鉴里会显示当前有多少。

### 2. 每周两段

每周先做一次**主行动**（听课、竞赛、翘课、表白、竞选…），再安排一次**周末**（补习、运动、兼职、陪家人、开黑…）。
周末的收益和代价都打折（约 55%），但**不占用整周**。所以「周末要不要也用来刷题」本身就是个取舍。

### 3. 属性与人物

八项属性：智力、体质、心情、社交、老师好感、综合素质、疲劳、违纪
（违纪累计到 **120 会被劝退**，心情或体质归零会休学）。

**人物姓名每局随机生成**：从百家姓 + 常见名字用字里取，同一个种子必定得到同一批人，
同一局里不会重名（连"名"都不重复，免得同学们互相叫起来分不清）。开局表单上不填姓名会随机给你一个，
也可以点 🎲 换一个。

八个角色对应 **7 个好感度键**（爸爸和妈妈共用"父母好感"），各有实际影响：

| 角色 | 好感度键 | 影响 |
| --- | --- | --- |
| 👨 爸爸 / 👩 妈妈 | `parents` | ≥75 每周多给 20 元；<30 每周掉心情 |
| 👩‍🏫 班主任 | `head` | 推荐名额、违纪处理、班干部竞选 |
| 🧮 数学老师 | `math` | 答疑加成、竞赛推荐 |
| 🧑 同桌 | `deskmate` | 好感 ≥70 每周回心情，≥85 有**友情结局** |
| 🧢 死党 | `friend` | ≥85 有专属成就；剧情线「团结广场后巷」的推进条件 |
| ⚔️ 老对手 | `rival` | 每次考试后按名次变化：你考好了他憋劲，你考砸了他反而来搭把手 |
| 💗 心动对象 | `love` | ≥35 才能表白，≥70 且分数不高会走**爱情结局** |

在界面里点「🌳 关系图」可以看树状图；CLI 里按 `r`。关系的冷热用颜色区分：
绿（≥70 亲密）→ 黄（40~69 还行）→ 红（<30 疏远）。

### 4. 行动（37 种）

- **学习**：认真听课、刷题（选科）、整理错题本、早读加晚练、考前突击、报补习班、给同学讲题
- **运动**：操场运动、参加校队训练
- **生活**：好好睡觉、食堂加餐、心理咨询、周末兼职、给初中生当家教、陪家人
- **娱乐**：网吧开黑、上课摸鱼、逛街放松、看闲书、写小说投稿、拍短视频、翘课去雨山湖
- **关系**：找老师答疑、和同桌一起自习、谈恋爱、表白、分手专注学习
- **特长**：社团活动、志愿服务、竞赛辅导
- **大事**：竞选班干部、改选科、报名艺考班、报名强基计划、报名综合评价、申请退学、报名参加高考（自由模式）

### 5. 知识、考试与分数线

单科得分 ≈ `满分 × (知识/100) × 心情修正 × 疲劳修正 × 体质修正 × 随机波动`，
知识收益是边际递减的：`收益 × (1 - 0.55 × 当前知识/100)`（最低保留 35%），越到后面提分越难。

**状态不是摆设**：心情从 0 到 100 对应学习效率 78% → 108%，疲劳超过 45 之后线性掉效率
（最低打到 55%）。也就是说"熬夜多刷两套卷子"经常是负收益——**先睡一觉再学，反而分更高**。
所以光刷题不睡觉一样考不好，而且选考的三门必须均衡。

### 6.5 志愿填报（v2.6 的新终局）

高考出分之后不是直接散场，而是最后一关：**六个格子怎么填**。

- 从 **16 个院校专业组** 里挑 **6 个平行志愿**（按顺序检索，够线即投，投中就不看后面的）。
- 每个专业组会标 **冲 / 稳 / 保**：`你的分数 - 今年投档线 >= 25` 是保，`>= 5` 是稳，其余是冲。
- **今年的投档线是波动的**：整年有一个 ±20 分的偏移，每个专业组还有自己的噪声，
  你只能看到一条"风声"（"今年题偏难，传要降" / "今年是大年，线要涨"）。所以"冲"是真赌。
- **单科要求会把偏科带进终局**：英语 ≥110、数学 ≥115、生物 ≥82 的专业不达标**直接退档**，
  志愿表上那张卡片会灰掉。
- **服从调剂**：六个志愿全滑档时，勾了还能被招生办捞进一个没填过的专业；不勾就是**落榜**。
- 特殊路线（保送 / 强基 / 体育 / 艺考 / 综评 / 出国 / 传媒）和已经定了**毕业去向**的局不走这一步。
- 自动对局会按"冲稳保"常识自动填表（`--no-volunteers` 可关掉），所以平衡脚本照样跑得到结局。


### 6.6 AI 对战（v3.0 的新玩法）

开局第一块就是**玩法**：单人模式，或者 AI 对战。选了 AI 对战再选**强度**：

| 强度 | 打法 | 实测平均高考分 | 说明 |
| --- | --- | --- | --- |
| 😴 轻松 | 佛系 | ~359 | 一周只认真学一段，其余时间在打球、看闲书 |
| 🙂 普通 | 均衡 | ~614 | 学一半玩一半，状态差会休息 |
| 😤 困难 | 卷王 | ~633 | 补最弱的一科、考前突击，开局多 2 点属性点 |
| 🔥 真实 | 竞赛 | 保送或 ~500 | 走竞赛保送路线，开局多 4 点属性点——它可能根本不参加高考 |

- **AI 那一局是真的第二局**：同一个 `createGame` / `performAction` / `resolveEvent`，
  同样的知识收益曲线、疲劳与心情、遗忘规则。它的分数是**打出来的**，不是凭空生成的。
- **它不作弊**：不会改你的任何数值。有测试逐条断言"同种子的单人局和对战局，玩家的开局随机流、
  属性、知识、回合数完全一致"——AI 连一个随机数都不许多吃。
- **节奏严格对齐**：钩子挂在 `endPhase`，玩家消耗掉一个阶段（含事件处理完）AI 才打一拍，
  所以玩家弹事件"暂停"时 AI 不会偷跑。
- **看得到的地方**：每次考试往校园日志塞一条对比；侧栏常驻「⚔️ 对战」面板
  （两边最近一次分数 + 名次 + 交手战绩）；结局页一张对战卡片（双方结局、总分、名次、胜负）。
- **没参加高考的结局也能比**：保送 / 强基 / 退学这类没有总分的结局按档次折算"等效分"
  （好结局 700 / 坏结局 380）并标注"等效判定"，免得保送在面板上输给 452 分。
- 分享链接：`index.html?demo=60&mode=versus&rival=hard&weeks=3&volunteers=0` 一键看到对战结局。


### 7. 剧情线（故事）

游戏里有 **7 条剧情线、共 36 章**，每章是一段有画面感的旁白，有些章节要你做选择：

| 剧情线 | 章数 | 讲什么 |
| --- | --- | --- |
| 🏠 家里那盏灯 | 5 | 夜宵、家长会、一碗汤的距离、高考那天的早饭 |
| 🧑 同桌的三年 | 4 | 借橡皮、谁先玩手机谁请奶茶、被撕掉的卷子 |
| 💗 雨山湖边的远路 | 5 | 跑操时那瓶水、传过三排桌子的纸条、三十五分的那天 |
| 👩‍🏫 办公室里的谈话 | 5 | 第一次被叫去、期中之后那张椅子、一个班两个名额 |
| ⚔️ 红榜上的另一个名字 | 5 | 差三分、一种奇怪的默契、考完之后 |
| 🧢 团结广场后巷 | 5 | 后巷那家网吧、天台上的约定、最后一碗小刀面 |
| 🏫 三年里的那些日子 | 7 | 军训、运动会、艺术节、采石矶春游、百日誓师、成人礼、毕业照 |

设计上有几个刻意的取舍：

- **强制排队触发**：条件一满足就排进队，下一次行动结束**一定**会弹出来，不会被随机事件挤掉。
  也不会连着几周全是剧情——两章之间至少隔 2 周。
- **七条线轮流推进**：引擎每次都挑「拖得最久」的那一章演，不会出现前两条线把名额占完、
  后面的线一章都轮不到。
- **有些章节要关系到位**（比如恋爱线要心动对象 ≥35 才好表白），所以一局演不完全部 36 章，
  想看完得换着玩法再来几局。
- **正文里的名字和代词都是这一局的**：`{deskmate}` 会变成"一萱"，`{deskmate.ta}` 会按性别
  变成"他/她"，不会出现"男同桌被写成她"。

在界面里点「📜 故事线」看进度和已解锁的正文；CLI 里按 `t`，或者 `npm run cli -- --auto --story`。

### 8. 校历：什么时候该发生什么

95 个随机事件和 37 个行动都登记在 `src/data/calendar.js` 里的一张时间表上，表长这样：

```js
lost_wallet:  { grade: [1, 2], note: '失主是高二学姐，你自己得是高一或高二' },
new_year_gala:{ term: 'autumn', minWeek: 4, note: '元旦晚会，元旦前后' },
military_training: { semester: 0, maxWeek: 2, note: '军训在开学头两周' },
run_class:    { grade: [1], note: '班干部竞选只在高一' },
```

字段：`grade`（1/2/3）、`term`（`autumn` 上学期 9-1 月 / `spring` 下学期 2-7 月）、
`semester`（直接指定第几个学期，0-5）、`minWeek` / `maxWeek`（本学期的第几周）、
`anytime: true`（明确表示"任何时候都合理"）。

这样做的好处：

- **不会再有荒谬的时间线**：高三不会捡到"高二学姐"的钱包，五月不会办元旦晚会，
  高二不会重新军训，毕业照只在高考前，百日誓师只在高三下开学。
- **行动也会解释原因**：高一报名艺考班会提示"现在不是做这件事的时候（只在高二）"。
- **有测试兜底**：`test/calendar.test.js` 强制要求"每个事件都必须登记时间表"，
  新增事件忘了定时间会直接测试失败；还有一条专门盯着钱包事件不许在高二以上出现。
- **周次会自动收拢**：把一学期设成 3 周时，`minWeek: 5` 会落到最后一周，而不是永远不触发。

### 9. 自由模式与元进度

- `--endless`：高三下学期会一直循环，每周照常上课考试，「报名参加高考」行动由你随时触发。
- 每局结束后会写入档案：结局图鉴解锁进度、成就收集、最好成绩、最近 20 局战绩（`npm run gallery` 查看）。

### 五个难度

| 难度 | 开局各科 | 遗忘 | 卷王平均分 | 985+ | 设计意图 |
| --- | --- | --- | --- | --- | --- |
| 🌤️ 轻松 | 16~30 | ×0.6 | 740 | 100% | 先把三年走一遍看看 |
| 🏫 正常 | 10~24 | ×1 | 617 | 25% | 标准：底子一般，学了会忘 |
| 🔥 困难 | 8~20 | ×1.3 | 517 | 0% | 收益低、忘得快、容错很小 |
| 💀 真实（地狱开局） | **48~62 且偏科** | **×4.5** | 513 | 0% | 起点在及格线，但爬不上去 |
| 🛠️ 自定义 | 自己调 | 自己调 | — | — | 8 根滑杆，规则自己定 |

**真实（地狱开局）** 是刻意做成"另一种难"：它的**地板高**（起点就是及格线，不会一路掉到专科），
但**天花板低**（边际递减下限压到 0.16 + 遗忘 ×4.5，60 分往上每提一分都很难），
而且开局明显偏科——会出现"政治 80、生物 30"，你得先把短板补起来，否则总分被死死拖住。

**难度设计意图**：

- **985（636 分）是需要努力的目标**：`diligent` 平均 617，四分之一的局能上。
- **清北（696 分）几乎只能靠竞赛保送**，或者把每一周都算得很准。这是刻意的——它就该很难。
- **佛系落在民办/专科**，摆烂必然翻车（35% 崩溃）。
- **"努力"不等于"一直学"，也不等于"只学一科"**：`crammer`（53 个学习回合，心情 19）只有 379 分，
  而 `balanced`（43.1 个学习回合，心情 95）拿到 577 分。**会休息 + 轮着学的人考得更好**，
  这是"不进则退"最想传达的东西。

想调平衡主要动这几个旋钮：`EFF.gainScale`（全局学习收益）、`EFF.forgetting`（遗忘规则）、
各难度的 `gain / forgetScale / slopeScale / gainFloor` / `POINT_BUDGET`（属性点预算）。
`node tools/tune.mjs` 可以扫参数横向对比，改完用 `npm run sim` 出正式报告。

### 没有浏览器时怎么验证界面

这个项目是在一个**开不了浏览器窗口、也开不了 Electron** 的环境里开发和验证的
（本机 Electron 连 `--version` 都会因为 crashpad 初始化失败而崩）。所以补了两个工具，
把"界面"变成"可以量、可以测"的东西：

```bash
node tools/layout-probe.mjs --port 4100
# 再开一个终端（Chrome 无头模式；本机窗口最小约 500px，更窄的屏幕请用真机或 DevTools 设备模拟）
chrome --headless=new --window-size=1440,900 --virtual-time-budget=30000 \
       --screenshot=out.png "http://127.0.0.1:4100/measure.html?demo=4&click=last"

node tools/preview-relations.mjs build/preview
python tools/svg-preview.py build/preview/relations.svg build/preview/relations.png
```

`measure.html` 量的是**真实的 index.html**（只是额外挂了一个外链脚本），会把数字画在页面上：

```
innerW=1424  innerH=749
docScrollW=1424  bodyW=1424      ← 和 innerW 相等，说明没有横向溢出
tabs=7  groups=学习,关系,特长,运动,生活,娱乐,大事
点击前 top=1471  点击后 top=199   ← 分组跳转确实滚到位了
```

`?demo`（网页版可用）会跳过开局表单直接开一局，`?demo=N` 还会自动走 N 步：
既能当"点开就能玩"的分享链接，也是上面这套截图流程的基础。

v2.5 起还能把"自定义人物"直接写进链接里，不开表单也能展示：

```
index.html?demo=6&preset=olympiad&nickname=闪电&flaw=frail&points=intelligence:4,math:2&difficulty=custom
```

v3.0 起玩法也能写进链接（`mode` / `rival`），另外两个参数是给"最短一局"的分享链接用的：

```
index.html?demo=60&mode=versus&rival=hard&weeks=3&volunteers=0
#          自动走 60 步   AI 对战  强度困难  每学期 3 周  跳过志愿填报 → 直接看到对战结局
```

（`preset` / `personality` / `nickname` / `avatar` / `flaw` / `points` / `difficulty` /
`mode` / `rival` / `weeks` / `volunteers` 都可用。）

## 在代码里使用引擎

```js
import {
  createGame, performAction, resolveEvent, playWeek, viewState, buyItem, endingCatalog,
  relationGraph, renderTreeText, storyCatalog, storyProgress,
} from './src/engine.js';
import { getStrategy } from './src/strategies.js';

const game = createGame({
  name: '小明',                          // 留空则随机一个中文常见姓名
  gender: '男',                          // 影响同桌/死党的性别与心动对象的性别
  nickname: '闪电',                      // 外号（留空则随机一个）
  avatar: 'panda',                       // 头像 id（见 creatorOptions().avatars）
  seed: 'demo',
  track: 'history',                      // 历史类
  electives: ['politics', 'geography'],  // 再选两门
  traits: ['memory', 'easygoing'],       // 天赋（选 2）
  personality: 'sharp',                  // 性格（选 1）
  flaw: 'frail',                         // 缺陷（最多 1 个，换属性点）
  points: { intelligence: 4, subjects: { math: 2 } },   // 属性点怎么分
  legacyPoints: 3,                       // 多周目传承点
  customCast: { deskmate: { name: '林小美', gender: '女' } },  // 自定义关系人物
  background: 'magang',                  // 家庭背景
  goal: 'c985',                          // 高考目标
  endless: false,
});

console.log(game.cast.map.deskmate.name);        // 这一局的同桌叫什么
console.log(renderTreeText(relationGraph(game))); // 关系树的文字版

// 手动推进：主行动 → 周末 → 下一周
performAction(game, 'listen');
performAction(game, 'sport');
buyItem(game, 'workbook');               // 买东西不花时间

while (game.pendingEvent) resolveEvent(game, game.pendingEvent.choices[0].id);

// 或者交给策略一次性打完整周
playWeek(game, getStrategy('diligent'));

console.log(viewState(game).calendarLabel, viewState(game).phaseLabel);
console.log(storyProgress(game));        // 七条剧情线演到哪了
console.log(endingCatalog().length, '个结局等你收集');
```

引擎是纯逻辑：CLI、网页服务、平衡脚本和测试全都调用同一份代码，不存在第二套规则。
存档是 JSON（`serialize` / `deserialize`），**v1 老存档会自动升级到 v2**；
v2.1 的存档里没有人物阵容和剧情记录，读进来会按种子把同一批人补回来。

### 想继续加内容？

- **加行动**：往 `src/data/actions.js` 加对象。`phase` 决定它属于主行动还是周末，`effect` 支持
  `stats` / `npc` / `knowledge`（`all`、`subject`、`weakest`、`random`、指定科目）/ `money` / `flags` / `risk`，
  需要特殊逻辑就写 `special(game, api)`。
- **加事件**：往 `src/data/events5.js`（校园日常）/ `events6.js`（因果链）或 `events.js` / `events2.js` / `events3.js` 加，
  `kind: 'choice'` 就是分支事件，`cond(game)` 控制触发条件。
  **每个新事件都要在 `src/data/calendar.js` 的 `EVENT_SCHEDULE` 里登记时间表**，否则 `npm test` 会红。
  加完跑一次 `node tools/check-events5.mjs` / `node tools/check-events6.mjs`，它们会把每个选项丢进真实引擎跑一遍。
- **加因果链**：第一环里写 `chain: { id: 'chain_xxx', delay: 4 }`，后续环写 `chainOnly: true`。
  最后一环如果想让这个选择决定毕业出路，用 **`graduationEnding`**（不是 `ending`）——
  `ending` 会当场结束这一局，`graduationEnding` 会等高考结束时结算。
- **加成就**：引擎里手写的写在 `collectAchievements()`；跟着事件走的直接加进事件文件导出的
  `CAMPUS_ACHIEVEMENTS` / `CHAIN_ACHIEVEMENTS`（`{ flag, icon, name, desc }`），引擎按 flag 自动收录。
- **加天赋 / 性格 / 缺陷 / 头像 / 角色模板 / 背景 / 目标 / 道具 / 人物**：都在 `src/data/character.js`、
  `src/data/items.js` 里加数据即可，修饰器字段见 `emptyMods()` 的注释。
  属性点项在 `POINT_BUY`（1 点换多少、上限多少），预算在 `POINT_BUDGET`。
- **改志愿填报**：专业池和投档规则在 `src/data/colleges.js`（`MAJORS` / `cutLineFor` / `resolveVolunteers`），
  结局的分数口径在 `src/engine.js` 的 `GRADUATION_ENDING_CAPS`。
- **加结局**：普通结局改 `src/data/school.js` 的 `COLLEGE_TIERS`，特殊结局加在 `src/engine.js` 的 `specialEndingFor()`，
  并记得在 `endingCatalog()` 里登记（图鉴会用到）；事件里可以直接用 `effect` 返回的 `ending: 'id'` 结束一局。
- **改内容而不改代码**：写个内容包（见上面的「热更新」）就够了——加事件 / 加道具 / 调平衡都不需要动 `src/`。
- **加剧情**：往 `src/data/story.js` 的 `STORY_ARCS` 里加一条线（或者给已有的线加一章）。
  章节字段见文件头的注释；正文写成 `(game, cast) => \`...\``，人名用 `${cast.deskmate.name}`、
  代词用 `${cast.deskmate.ta}`，**不要写死"张昊""王老师"**——那些名字每局都不一样
  （而且玩家可以自己给同桌起名，写死了就会串戏）。
  `week` 是"第几周之后才能触发"，一条线里要保持递增。
- **调平衡之外别忘的三件事**：`npm test`（383 个测试，包含剧情结构、姓名生成、
  自制人物、内容包、事件日历、AI 对战的时间线与随机流隔离、排行榜的排序与后端降级、
  两种自托管后端的边界（白名单 / 校验 / 限流），以及发布页的链接 / 素材 / 交互守门测试）、
  `python tools/build-pages-shots.py && node tools/build-pages.mjs`（界面改过之后重出发布页素材与产物）、
  `node tools/preview-relations.mjs` + `python tools/svg-preview.py`（不用开浏览器就能看关系树排版）。
- **不知道该做什么的时候**：翻 [ROADMAP.md](./ROADMAP.md)，那里按 P0/P1/P2 排了短期 / 中期 / 长期建议，
  每条都带工作量和验收标准。
